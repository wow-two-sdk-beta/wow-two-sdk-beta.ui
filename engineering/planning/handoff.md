## Wave 4b (2026-07-13, 4 parallel agents) — gestures · selection · media · animation

- **`gestures`** (90) — `useDrag` binds move/up to `window` in addition to requesting pointer capture, so a failed `setPointerCapture` degrades instead of freezing the drag mid-gesture. `useLongPress` deliberately takes NO capture (a hold that leaves the element should cancel). A test caught a real bug: naive trailing-window velocity returns **zero** for a genuine flick, because `pointerup` repeats the last `pointermove` coordinates — `windowedVelocity` trims the stationary tail, but abandons the trim if the pointer rested longer than the window (flick→hold→release is not a flick).
- **`selection`** (160) — canonical model, **`DataTable` not migrated**. Known divergences to resolve in the migration: `DataTable` floats nullish to the TOP on `desc` (model keeps nullish last both ways) · `DataTableSort` is `{columnKey, direction} | null` vs the model's `SortDescriptor[]` · `DataTable` refuses to sort an accessor-less column while `readField` falls back to a property read · `Listbox` selects by arbitrary value with a pluggable equality fn, which the key-based model cannot express · `SortDirection` now exists in two subpaths.
- **`media`** (63) — `DOMException`-name → status mapping is the module's real value. `OverconstrainedError` maps to `failed`, NOT `unavailable`: the device usually exists and the caller's constraints are the bug, so calling it "no camera" would hide a fixable consumer mistake. `getMediaSupport` ranks a present `getUserMedia` above `isSecureContext === false`, and never reads `undefined` (Node/SSR) as insecure.
- **`animation`** (57) — `finished` settles on finish OR cancel and never rejects (a rejecting cancel is the classic WAAPI footgun). Falls back to committing the final keyframe when WAAPI is missing, reduced motion is on, or `duration: 0`. Distinct from `Presence`: that is the *lifecycle* primitive (holds a child mounted past `isPresent={false}`); this is the *geometry* layer for elements that stay mounted and move. No motion tokens exist in `themes/`; reused `TransitionExtensions.duration.default` (200ms).

## Wave 5 (2026-07-13) — virtualization · observers · crypto · sync

- **`virtualization`** (76) — no dependency added; `@tanstack/react-virtual` deliberately not installed. Fixed and variable paths are asserted to return *identical* ranges across ~1600 offset/viewport/overscan combinations, because a divergence would only surface as a one-row flicker at specific scroll positions. Scroll anchoring compensates only when the re-measured item ends at or above the fold, and is applied as an accumulated delta in a layout effect after the spacer grows — applied synchronously it gets clamped against the stale container height and silently lost.
- **`observers`** (24) — Intersection + Mutation only; ResizeObserver already ships in `foundation/hooks` and was not duplicated. `useIntersectionObserver` shares ONE observer instance across targets (one-per-item is the classic long-list perf mistake).
- **`crypto`** (68) — digests checked against published FIPS 180-4 vectors, not self-consistency. `randomString` uses rejection sampling (`% alphabet.length` on a raw byte skews the distribution). `subtle.digest` needed a documented `as BufferSource` cast: TS 5.7 narrowed `BufferSource` to exclude `SharedArrayBuffer`-backed views that plain `Uint8Array` still admits.
- **`sync`** (17) — **two agents died mid-task on a network error**; `observers` was recovered intact, `sync` had complete source but ZERO tests, which I wrote. Writing them surfaced a real ordering defect in `LeaderElection.release()`: it posted `resign` *before* `stepDown()`, so with a synchronous transport the peer's immediate claim was answered by the still-leading tab, the claim aborted, and the handover was lost until the lease expired (both tabs sat as followers). Fixed by stepping down first. **Lesson: a dead agent's slice can typecheck and lint clean while being untested and wrong.**

## Wave 6 (2026-07-13) — async · undo · clipboard · speech

- **`async`** (63) — a test caught a real design flaw: `sequential` first delegated to `mapLimit(tasks, 1, …)`, which preserves order but **does not short-circuit** — task 3 ran after task 2 rejected, because the limiter's queue never learns of a failure. Dangerous for the sequential-migration use case it documented; replaced with a real short-circuiting loop and `mapLimit`'s doc corrected. Also: TS narrows `signal.aborted` to `false` after one check, breaking every post-`await` re-check — route through an `isAborted()` call to re-widen.
- **`undo`** (61) — `HistoryCore` owns the array+cursor so truncation/limit/coalescing/`transact` exist once; the two flavors differ only in payload and merge fn. `useUndoableState` is deliberately uncontrolled-only: a parent changing the value out of band would desync `present` from the anchor each entry's `before` was captured against.
- **`clipboard`** (89) — the existing `useClipboard.copy` resolves `Promise<void>` on success AND failure, so a non-React caller cannot detect failure and `denied` is indistinguishable from `failed`. This slice returns the same discriminated result from hook and non-hook paths. `share`'s private `copyToClipboard` could delegate to `copyText` with a one-line status widening — not done, out of lane.
- **`speech`** (83) — `listVoices` awaits `voiceschanged`; `getVoices()` is empty on first call, which is the API's most common bug. Mutation-verified: resolving with the first empty list kills 4 tests. Recognition error codes reuse `foundation/media`'s vocabulary; `lang` reuses the i18n locale rather than a second language type.

- **`collections`** (138) — deliberately exposes **no sort**, so `compareStrings` has exactly one home (`selection/applySort`); adding `sortBy` here would have been the second sort engine. Reuses `utils/Equality.shallowEquals` rather than reimplementing. Cyclic tree: rows **on** the cycle become roots with the upward link severed, rows **below** it nest normally — verified nothing is dropped or duplicated.
- **`datetime`** (131) — **adoption is NOT a mechanical swap, decide first.** The date components (`Calendar`, `RangeCalendar`, `MonthGrid`, `RecurrenceEditor`, `Gantt`, `EventCalendar`) don't hand-roll `Date` math; they all route through `presentation/forms/DateExtensions.ts`, which is **Temporal**-based, and `http/temporalReviver` already upgrades inbound wire strings to `Temporal.*`. - **`validation`** (74) — the `~standard` bridge is verified against `forms-engine`'s real `StandardSchemaV1` and run through the real `runStandardSchema`, so a validator built here drops into the forms engine with no adapter. `forms-engine` can later import the spec type from here and delete its copy (downward import, boundary-legal; the reverse never was). `Input` is `TOutput` not `unknown` — a validator declaring `Input = unknown` is not assignable to the one-arg `StandardSchemaV1<TValues>` consumers spell.

- `CLAUDE.md` is at the **repo root**, not the package dir. `@src/*` alias resolves tests → source. Vitest path filters are substring matches.
